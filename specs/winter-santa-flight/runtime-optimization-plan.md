# Santa runtime optimization implementation plan

**Goal:** Preserve the current scene while reducing repeated CPU work, startup UI blocking and excessive render frequency.

**Architecture:** Cache particle birth anchors. Use a DOM-free Three.js scene runtime shared by a dedicated OffscreenCanvas worker and a main-thread fallback. A lightweight DOM controller selects the backend and forwards infrequent lifecycle messages. A small pure governor controls frame cadence and resolution.

**Tech stack:** Existing TypeScript, React, Three.js, browser workers, Vitest and Playwright; no new dependencies.

**Spec:** `runtime-optimization-spec.md`.

## Global constraints

- Preserve model topology, visual materials, 192 particles, routes and 48-second cadence. No LOD, new dependencies or CSS redesign. Deployment is outside the implementation scope.
- Main-thread lifecycle gates apply equally to the worker and fallback. Never import Three or request assets before eligibility.
- Preserve all unrelated working-tree edits and the existing development-server output.
- Use English project files, strict types, intent comments above functions and VoidFunction where applicable.

## Review focus

- Late asset/compile completion after offscreen/unmount/reduced-motion changes cannot restart work.
- Fallback after canvas transfer must allocate a fresh canvas and stop the failed worker before using the fallback.
- Absolute animation time affects sleigh oscillation, so identical birth numbers in different cycles must not reuse incompatible anchors.
- High-refresh skipped frames and low-tier cadence must not advance the timeline incorrectly or trigger false recovery.
- Existing still-preview initial sizing and portal movement must not become blank or render a stale pose after asynchronous preparation.

## Task 2: Worker renderer, startup and live frame control

**Files:** Refactor `santaRenderer.ts` into the shared scene runtime; create `santaController.ts`, `santaWorkerProtocol.ts`, `santaWorkerRuntime.ts`, `santa.worker.ts` alongside it. **Interfaces and responsibilities:**

- `santaController.ts` exports `SantaRenderer` with existing `setRunning(boolean)`, `seek(number|null)`, `dispose: VoidFunction`, and `createSantaController(container: HTMLDivElement, initialTime: number|null): SantaRenderer`. No runtime Three import. Factory returns immediately and retains latest requested run/seek/size through preparation. Component imports it dynamically after eligibility, stores the handle, and calls `setRunning(true)`; remove component-level asset preparation. Component handles disposal/gates, controller handles asynchronous backend creation. Existing preview API remains unchanged.
- `santaRenderer.ts` retains `prepareSantaAssets()` and exports `createSantaScene(options): Promise<SantaScene>`. `SantaScene` extends `SantaRenderer` with `resize(width,height,pixelRatio): void`. Options contain an explicit canvas (`HTMLCanvasElement | OffscreenCanvas`), width/height/device ratio, initial preview time and `onState` callback. Pass an explicit scheduler with `requestFrame`, `cancelFrame`, `setTimer`, `clearTimer`, `now` so tests and the two runtimes do not depend on window. Exact structural interfaces belong in the protocol/types file with type-only imports. Async factory allocates the unchanged scene, calls `renderer.compileAsync(scene,camera)` while all model/trail programs are included, and returns the paused scene; no automatic initial render. `seek`/`setRunning`/`resize` trigger only necessary draws after readiness. Require a local `AbortSignal` in scene options. Reject before allocation when already aborted, race compilation against cancellation, and immediately release resources/listeners on abort or context loss even while compilation remains unresolved. Keep cleanup idempotent across failures, late shader completion and normal disposal. Keep context-loss safety. No DOM element styling/append/removal, ResizeObserver, dataset or window in the scene runtime; `renderer.setSize(width,height,false)` supports offscreen.
- `santaWorkerProtocol.ts` defines typed discriminated inbound messages: init (canvas, size, device ratio, previewTime, isRunning), resize, run, seek, dispose. Outbound: hello, ready, state (phase/running/quality metadata as needed), error, disposed. Validate incoming unknown messages with small guards for discriminants, numeric bounds/finite values and payload shape. Validate init canvas in worker with instanceof OffscreenCanvas. Do not add an RPC framework.
- `santaWorkerRuntime.ts` owns the testable worker lifecycle with injected postMessage/close/scheduler and renderer-module loader; no Three import until initialization. Cache prepared module, retain latest configuration. Await assets, then recheck running/disposed before allocating the scene. If paused, hold prepared data and create only after a run=true. If paused during compile, keep the finished scene paused and do not draw until eligible. Apply newest viewport and seek before first run. Dispose late-created scenes and never emit ready after disposal. Entry `santa.worker.ts` wires actual worker events and scheduler; use worker RAF where available, a cancellable ~16.67ms timer fallback otherwise. Emit hello before loading Three/assets.
- Controller attempts `new Worker(new URL('./santa.worker.ts', import.meta.url))` only when Worker and transferControlToOffscreen exist. Wait for hello before transferring. Use a 3-second hello deadline; after init allow 20 seconds of active startup time (pause this deadline when ineligible) for ready. Errors, messageerror, invalid replies, postMessage/transfer/constructor failures and timeout terminate the worker and start the shared main-thread runtime once. A transferred canvas is replaced. Fallback preparation rechecks running/disposed before context allocation. Never retry after fallback failure; mark unavailable and keep the page usable. Latest run/seek/size always wins. Expose `data-backend=worker|main`, existing phase/status/running and optional tier for tests. Avoid per-frame messages or DOM writes.
- On controller disposal cancel timers/ResizeObserver and listeners; main runtime dispose is synchronous. Stop worker with a dispose message and terminate on disposed acknowledgement or after at most 1 second; failed posts terminate immediately. Late callbacks do nothing. Resource release must also work while shader warmup is pending.

## Review refinement: cancellable shader preparation

The final review found that an `isDisposed` predicate checked after `compileAsync` cannot reclaim resources while that promise remains pending. Replace the predicate in local scene options with a required `AbortSignal`; the controller and worker runtime each own an AbortController for their local scene lifetime and abort during disposal. The worker protocol messages do not transfer signals. The factory rejects before allocating for an already-aborted signal, registers cancellation cleanup before waiting, and releases all created resources/listeners immediately on abort or context loss during warmup. Race shader readiness with cancellation so a never-resolving GPU promise cannot retain the returned initialization promise. Cleanup is idempotent across abort, normal disposal, failure, late compile resolution and context loss. Keep all existing eligibility gates and normal frame behavior. Test an unresolved compile and assert prompt rejection and resource/listener cleanup before resolving it; also verify controller/runtime disposal actually triggers cancellation. Replace the forbidden double assertion in the worker entry with a single documented structural assertion or properly typed scope adapter.
