# Festive finish implementation

## Scope and diagnosis

The shared 1.1-second cycle and offsets of only 0.025 cycles made the four animals appear synchronous. The body had smooth geometry with a very fine 64px bump map, and antlers had no decorations. The confirmed flight direction is top-right entry followed by leftward levelling and left exit, then the existing close return from left to right.

Implement only in `SantaFlight/santaModel.ts`, `santaTrajectory.ts` and impacted model/route tests; update the main spec and append tasks/evidence. Renderer, host and public API need no change unless an actual defect is found. Keep the existing preview and dependency manifest. Use current strict typing, intent comments and VoidFunction rules.

## Model

1. Give each Animal fixed deterministic `period`, `phase` and modest amplitude/lead values. Suggested periods in seconds: `[1.03, 1.18, 1.09, 1.24]`; offsets in cycles `[.08,.36,.65,.9]`; amplitudes `[.96,1.03,.98,1.06]`. Derive that animal's bounded phase directly from seconds modulo its own period, and use it for both stride and local bob/pitch. Keep the existing periodic monotone Hermite joint curves and anatomical bend signs. Use small per-animal side lead differences. Do not introduce per-frame randomness or accumulators. Preserve the sleigh's separate restrained motion.
2. Place eight small light cores on each deer's existing antler tips (four tips per side), using the actual antler control-tip coordinates plus the current `[.2,-.18,0]` antler offset. Offset a little outward if required to keep cores visible above the bone. Use restrained warm gold, icy cyan and berry-red colors. Bake translated/scaled copies of the existing small sphere into one shared colored BufferGeometry, disposing construction copies. Use one shared vertex-colored MeshBasicMaterial with tone mapping disabled, nested in an antler-lights Group so rigid merging cannot remove the named parts. This adds one core draw per deer, not one draw per bulb.
3. Add a shared Points geometry with the eight matching centers/colors and one shared PointsMaterial using a small deterministic radial-alpha DataTexture, additive blending, depth test, no depth write, and normal perspective size attenuation. Start point size around .25 and opacity .7; tune from the actual Model render so halo is wider than the core but restrained in flight. This adds one halo draw per deer. Do not add per-bulb lights, shadows or bloom/postprocessing. Widen the owned material Set to the precise common Material type to dispose the additional material kinds; retain existing typed MeshStandardMaterial helpers. Register new geometries/textures/materials exactly once. Keep core/halo nodes meaningfully named.
4. Replace only the fur relief texture with a deterministic 256px short directional fiber pattern; leave cloth/leather textures alone. Keep the existing brown/pale vertex coloration and restrained roughness/bump (start body bumpScale near .014).
5. Add one shared, bounded short-fur geometry in a nested Group per body, reusing bodyFur material. Sample about 384 eligible body surface vertices/normals/colors deterministically. Exclude muzzle/eyes and avoid excessive underside density. Create very short tapered crossed/back-wound hair triangles leaning toward a body-surface-projected comb direction (roughly backward/down), rather than long radial spikes. Typical protrusion .02–.045 raw units, narrow base .008–.015. Copy surface colors and valid UV/normals. Keep the original named continuous-body mesh and its watertight geometry unchanged. One fur draw per deer, no alpha sorting, simulation, shader patch or new runtime allocation. At flight scale detail should be subtle; in Model view the neck/back outline should look softly textured, not like grass or a hedgehog.
6. Target original budgets: fewer than 180k actual triangles, 45 distinct geometries and 125 mesh/point draws. Expected additions are four core, four halo and four fur draws, around 12k triangles, and one small halo texture. If the actual view is noisy, first reduce hair count/length or glow size; do not build a larger fur renderer.

## First route

Set distant normalized cubic controls x `[.98,.85,.30,-.45]`, y `[-.35,.45,.38,.25]`, depth `[-18,-17,-11,-6]`. Mirroring the former distant X controls supplies top-right entry, leftward movement through the center and complete left exit. Existing depth-aware tangents and upright frame bases orient the animals and sleigh along that route automatically; do not manually flip meshes. Keep exact cubic timing and arc-spaced following. Preserve the close route, its portrait Y adjustment and all phase timings.

The aside/header still paint above the scene. Project complete actual bounds for top entry/left exit at both distant pass boundaries on desktop, portrait and landscape. Verify an initially downward heading that levels leftward, finite upright frames, correct analytic derivatives and opposite horizontal directions for the distant pass and the later close pass. Record this direction correction separately from the earlier finish acceptance. For this literal-control correction, targeted model/trajectory tests, scoped lint/format and actual desktop/mobile frames provide validation; do not repeat the full production build unless a further structural change or failure warrants it.

## Rendered glow refinement

Actual Model captures showed that a fixed Points size of .25 was mostly hidden by the light cores. Use a base halo size around .65 multiplied by the current object's world scale in its onBeforeRender callback (the length of the X basis column in matrixWorld is sufficient). All four animals share a uniform scene scale; keep the shared material. This gives a soft halo outside the core in Model view and proportionally smaller glows during flight, using standard PointsMaterial without a shader patch or extra public API. Keep opacity near .7 and refine only if the actual image is noisy.
