# Motion refinement

## Requirements

The current flight needs three corrections requested after actual preview review:

- Replace the mechanical leg rotation with a readable collected/extended gallop. Front and hind limbs must fold in their anatomical directions, with a small left/right lead offset and subtle coordinated body motion.
- Make both flights visibly arcuate. The front pair leads; the rear pair and sleigh follow the same curve at separate distances and turn later. Harness connections must follow their attachment points without floating or stretching away.
- Use the full viewport for flight, including the preview's Distant/Near/Live modes. Enter and leave through a horizontal screen edge, with the complete team outside before a hidden phase. Keep the Model inspection view contained and readable.

Preserve the red cap, model artwork, four animals, cycle timings, winter-only lazy loading, reduced-motion behavior, offscreen/tab suspension, resource disposal and shell layering. No unrelated workspace changes, new dependencies, commit or deployment.

## Diagnosis

The current gallop is a set of independent sine rotations, with lower limb bend directions reversed for front versus hind limbs. A single rigid pivot moves every component together. Its arbitrary yaw/bank is independent from the route tangent. Hand reins alone receive a small wave, while pull traces stay fixed. Production already uses a body-level fixed canvas, but every preview mode uses a clipped content-sized stage. Near flight starts below the viewport, which obscures the intended side entry.

## Implementation plan

Use the existing Three geometry and curve APIs. Do not introduce a physics engine, animation dependency, worker or new art pipeline for this correction.

1. Add visibly curved normalized cubic routes with all endpoint Y values inside the viewport. Suggested controls `(x,y,depth)`: distant `(1.35,.10,-18), (1,.50,-16), (.25,.50,-10), (-.55,.27,-6)`; near `(-.45,.90,8), (.10,1.02,13), (.78,.78,5), (1.65,.12,-16)`. The near midpoint must cross the real Home heading. Keep 12/2/9/25-second phases and finite/modulo handling. Expose the phase progress and a Three Curve<Vector3> which samples the exact perspective-projected route in world space. Share camera distance/FOV constants with the renderer. Provide an analytic tangent; precompute arc lengths only when viewport dimensions change.
2. Reuse three formation frames, each containing a Vector3 position and Quaternion rotation. Sample front pair at current travelled arc length, rear pair one spacing behind and sleigh two spacings behind. Spacing is the original raw X difference of four units converted by the existing model normalization and display scale. Extrapolate the start tangent for negative trailing distance; never clamp trailing frames together at entry. Build orientation from tangent X, world-up and their cross product so a leftward pass remains upright. Remove arbitrary rigid yaw/bank from live flight. Keep the existing Model fit.
3. Extend the model API minimally: expose normalized `spacing: number`; let `animate(seconds, formation?)` accept three reusable frames plus display scale. Export precise formation types. Model mode restores the existing centered/normalized rig and original component positions. Flight mode uses world-space frames inside an identity rig; each deer retains its pair's lateral offset and small local body motion, and each component uses the model normalization times display scale. The renderer's pivot is identity during flight. Attach the warm light locally to the sleigh.
4. Replace leg sines with a smooth periodic keyed stride, roughly 1.1 seconds per cycle, containing extension, sweep and folded recovery. Suggested front lower angles stay negative (roughly -.1 to -1.5 radians), hind lower angles positive (.1 to 1.4); upper swings stay moderate (roughly -.9 to .85). Use a small side lead offset and small animal offsets, rather than unrelated motion. Use periodic cubic Hermite interpolation with cyclic neighbor tangents: preserve C1 wrap and avoid making all joints stop at every shared key. Keep all buffers/geometry fixed. Coordinate bob/pitch with this stride. Final values may be refined from actual rendered motion without changing the model or requirements.
5. Track all six hand/pair/sleigh traces, their original vertex/normal buffers and original endpoint frames. Transform each original vertex/normal by its start and end component frames, blending by longitudinal fraction. This preserves curved original tubes while their ends follow the moving hands/harness/attachment points. Apply only restrained sag; endpoint offsets stay zero. Reuse scratch vectors and existing attributes, avoid per-frame geometry creation or recomputing whole-mesh normals. Disable frustum culling for the few moving thin traces so stale construction bounds cannot hide them. Same behavior must work in Model mode with its gentle bob.
6. Retain a single preview renderer/canvas when switching modes. Move its existing host between the inline Model stage and a body-level fixed portal for all flight modes; update its CSS class and let ResizeObserver refit it. A host ref and the existing mode effect are sufficient. Observe the real preview section for eligibility, keep cleanup/race guards. Update preview text to explain full-window flight. All controls remain usable and the shell stays above the scene.
7. Update impacted pure/model/renderer/host/browser tests, including model mocks for the extended API. Require visible arc deviation, finite upright tangents, constant arc spacing, entire-team projected bounds outside at phase boundaries on desktop/portrait/landscape, different component headings on a turn, wrapping finite gait with correct knee/hock bend, attached reused trace buffers, and unchanged disposal. Browser checks assert full-viewport flight host bounds and canvas identity across Model/flight switches. Inspect real animated frames on desktop/mobile; a sampled contact sheet or short recording must show the stride and delayed turning, beyond static assertions.

Use VoidFunction for zero-argument void callback types in changed files, precise TypeScript and intent comments. Reuse the shared voidFunction for intentionally empty callbacks if one exists; do not perform a repository-wide callback migration.

## Ruling after actual viewport review

The first real Home frames confirmed the full viewport and aside occlusion, but uniform world-distance speed made the close team reach the right edge too early: at 17.5 seconds it was already small and beyond the heading. Keep fixed arc-distance spacing between components, while timing the leader by the authored cubic parameter. In the renderer, interpolate the cached route arc-length table at `pose.progress` and pass that distance divided by total length to `sampleSantaFormation`. This keeps the sampler's distance contract and lets the visible close pass linger naturally. Add a renderer-level assertion that the leading frame follows `route.getPoint(pose.progress)` within arc-lookup tolerance.

On portrait viewports the actual Home heading is vertically centered; the original lower-screen pass missed it. For the near route only, scale the normalized Y controls by 0.72 when aspect is below 1. Keep the same depth and X controls, side entry/exit and tangent derivative. Apply the adjusted Y controls consistently to point and derivative sampling. Recheck complete-team boundary bounds and actual portrait heading overlap. No new configuration or dependency is needed.
